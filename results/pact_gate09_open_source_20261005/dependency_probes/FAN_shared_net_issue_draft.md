At FAN_ATPG commit `26b2b36c0e9db11a4b6d9e759df6e44357121f39`, `Circuit::createCircuitPmt` adds every other pin on a primitive input net to its fanin vector. A receiver pin that is neither an internal output nor a public input falls through with `faninID=0` and is added as a spurious driver.

A minimal fixture uses `MUX2_X1 U_COMPOUND (.A(a), .B(b), .S(s), .Z(d))` feeding one `SDFF_X1`. The supplied MDT model connects S to both an AND input and an inverter input. The resulting primitive fanin count exceeds the primitive's input count and its exhaustive MUX truth table fails. The narrow fix is `else { continue; }` after the two legitimate driving-pin cases in `createCircuitPmt`. It does not change ATPG search, fault extraction, compression, or library models. This correction is independent of the previously isolated compound-cell level/arity defects.

Separately, `ReportFaultCmd::exec` leaves compound internal fault sites unresolved when no public cell pin exists. Its input loop also considers a following output port, causing duplicate output names for internal MUX input faults. The reporting fix selects input pins only and falls back to a stable `instance/primitive/pin` name for internal sites. After the connectivity correction, old/new reporting binaries preserve every fault class's state and equivalence weight, unique public identities, and selected-state filtering.

Focused regressions: the independent MUX fanin and exhaustive 16 input/FF-state truth-table tests both fail before and pass after the connectivity fix. Existing AOI211 depth/arity/exhaustive truth and minimal ATPG tests pass. A simple-cell reporter control passes. Compound reporter tests on the minimal fixture and a fixed larger pattern set pass with unchanged weighted counts on matched corrected circuit construction.
